5 algorithms. Pick one. Compose them. Write your own.

Fixed Window

Counts requests in a fixed time slot that resets at a hard boundary. Simple and cheap — best when exact boundary behaviour doesn't matter.

  • ✅ Lowest memory footprint
  • ✅ Simplest to reason about
  • ⚠️ Boundary bursts possible
Best for: internal APIs, rough caps, dev environments
import { createLimiter, FixedWindow,
         MemoryStore, byIP } from 'ratelimit-engine'

const limiter = createLimiter({
  algorithm: new FixedWindow({
    limit:    100,
    windowMs: 60_000,   // 100 req/min
  }),
  store: new MemoryStore(),
  keyBy: byIP,
})

app.use(limiter.express())

Sliding Window

Weighted approximation of a true rolling window. Eliminates the boundary spike problem of Fixed Window by weighting the previous slot.

  • ✅ No boundary spikes
  • ✅ Smooth, consistent limiting
  • ⚠️ Slightly higher store usage
Best for: public APIs, user-facing endpoints
import { createLimiter, SlidingWindow,
         RedisStore, byUser } from 'ratelimit-engine'

const limiter = createLimiter({
  algorithm: new SlidingWindow({
    limit:    100,
    windowMs: 60_000,
  }),
  store: new RedisStore({ client: redis }),
  keyBy: byUser,
})

Token Bucket

Tokens refill at a fixed rate up to a maximum capacity. Allows short bursts while enforcing a long-term average rate.

  • ✅ Burst-friendly
  • ✅ Natural feel for users
  • ✅ Ideal for API gateways
Best for: API gateways, developer APIs, SDKs
import { createLimiter, TokenBucket,
         RedisStore, byAPIKey } from 'ratelimit-engine'

const limiter = createLimiter({
  algorithm: new TokenBucket({
    capacity:   100,  // max burst
    refillRate: 10,   // tokens/sec
  }),
  store: new RedisStore({ client: redis }),
  keyBy: byAPIKey,
})

Leaky Bucket

Requests queue up and drain at a fixed rate regardless of burst. Excess beyond capacity is dropped immediately.

  • ✅ Strict output rate
  • ✅ Smooths traffic spikes
  • ⚠️ No burst allowance
Best for: payment APIs, webhook delivery, downstream protection
import { createLimiter, LeakyBucket,
         RedisStore, byIP } from 'ratelimit-engine'

const limiter = createLimiter({
  algorithm: new LeakyBucket({
    capacity: 100,  // queue depth
    leakRate: 10,   // requests/sec
  }),
  store: new RedisStore({ client: redis }),
  keyBy: byIP,
})

Composite

Combine multiple algorithms with ALL (every must pass) or ANY (one must pass). Enforce burst caps AND hard daily limits simultaneously.

  • ✅ Multi-policy enforcement
  • ✅ ALL and ANY modes
  • ✅ Strictest retryAfter returned
Best for: tiered plans, enterprise SLAs, complex policies
import { createLimiter, Composite,
  TokenBucket, SlidingWindow,
  RedisStore, byUser,
  COMPOSITE_MODES } from 'ratelimit-engine'

const limiter = createLimiter({
  algorithm: new Composite({
    algorithms: [
      new TokenBucket({ capacity: 50, refillRate: 10 }),
      new SlidingWindow({ limit: 500, windowMs: 86_400_000 }),
    ],
    mode: COMPOSITE_MODES.ALL, // both must pass
  }),
  store: new RedisStore({ client: redis }),
  keyBy: byUser,
})

Up and running in minutes

1

Install

npm install ratelimit-engine
# For Redis support (optional)
npm install ioredis
2

Configure

import { createLimiter, TokenBucket,
         MemoryStore, byIP } from 'ratelimit-engine'

const limiter = createLimiter({
  algorithm: new TokenBucket({ capacity: 100, refillRate: 10 }),
  store:     new MemoryStore(),
  keyBy:     byIP,
  failOpen:  true,
  onBlocked: (ctx, result) => {
    console.warn(`Blocked ${ctx.ip} — retry in ${result.retryAfter}s`)
  },
})
3

Apply to your framework

// Express
app.use('/api', limiter.express())

// Fastify
fastify.addHook('onRequest', limiter.fastify())

// Framework-agnostic
const result = await limiter.check({ ip, method, path, headers })
if (!result.allowed) { /* handle 429 */ }

Architecture

Four clean layers. Each independently replaceable.

Your Application
Express · Fastify · Any HTTP framework
↓ req / ↑ res
Framework Adapters
Extracts RequestContext → calls engine → writes headers
↓ RequestContext / ↑ RateLimitResult
Engine Core
KeyResolver · RateLimiter · HeaderWriter · Hooks · Logging
↓ key + store
Algorithm Layer
FixedWindow · SlidingWindow · TokenBucket · LeakyBucket · Composite · Your own
Store Layer
MemoryStore · RedisStore (atomic Lua) · Your own
